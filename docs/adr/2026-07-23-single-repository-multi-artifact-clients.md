# ADR：单仓、多制品与共享本地后端

日期：2026-07-23

## 决策

GameForge 保持单仓。现有 `apps/tui`、`apps/workbench` 和 `apps/desktop` 与本地后端分别构建、下载和发布，但共享同一个版本化公开契约。CodeArts 启动适配依赖用户已安装的 CodeArts，不维护或重新分发 CodeArts 源码和客户端。

CLI 与 GUI 共同连接本地后端。后端自动发现或拉起，保持独立进程与公开协议边界，是 Task、Run、MCP Audit、事件发布和并发控制的唯一权威。两个客户端可同时连接；竞争同一状态变更时，由后端以乐观并发控制或租约拒绝其中一个操作，并返回可解释冲突。

后端在有限兼容窗口支持当前和上一稳定客户端契约。客户端仅强制业务语义一致，不强制功能集合、交互步骤或界面一致。

## 理由

当前所有制品由同一负责人维护，依赖共同后端且需要跨入口业务语义验证。单仓保留跨契约、后端和客户端的原子变更，同时使用 workspace 包边界防止实现耦合。独立构建与发布不需要独立 Git 仓库。

## 测试边界

- `verify:backend`：共享契约、Relay 和 MCP 的构建、类型检查与测试。
- `verify:cli`：TUI 与 CodeArts 启动适配的构建、类型检查与测试。
- `verify:gui`：Workbench 构建与单元测试、真实浏览器 smoke、Tauri 壳的构建、类型检查与测试。
- `verify:compat`：执行现有 MCP 工作流集成测试，作为当前跨包兼容门禁。
- `verify`：聚合全部边界与兼容门禁。

后续应新增“后端当前版 x CLI/GUI 当前版和上一稳定版”的兼容矩阵，并覆盖两个入口对同一 Task 的并发状态变更。

## 后果

暂不分仓，继续维护现有 TUI、Workbench 与 desktop 边界；不把客户端状态界面改造成第二套 Agent 循环。若未来出现强制权限隔离、不同维护团队或可测量的单仓规模瓶颈，再重新评估分仓。
