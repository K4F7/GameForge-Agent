# CodeArts 可见无人值守验收 Patch 要求

日期：2026-07-22

## 背景

当前 CodeArts 实时验收已经能够在后台启动 ConPTY、采集 TUI 屏幕帧，并通过无头浏览器生成截图、视频和诊断证据。但该实现属于“后台可视化证据采集”：运行期间不会弹出终端或浏览器窗口，用户无法实时观察 CodeArts TUI 和自动验收过程。

这不满足“可视化且 Agent 无人值守测试”的完整要求。后续 Patch 必须同时实现：测试全自动执行、用户可实时观看、证据可复核。

## Patch 目标

新增显式的可见无人值守运行模式。在该模式下：

1. 自动显示一个独立的 CodeArts 原版 TUI 被测窗口，并弹出真实可见的浏览器窗口打开原版 OpenChamber GUI。
2. 两个被测窗口保持独立；不得把 CodeArts TUI 嵌入 OpenChamber，也不得使用伪造终端或静态日志代替真实会话。
3. Agent、MCP、浏览器玩法验证和阶段推进继续自动执行，不要求用户点击、输入或确认。
4. 可见窗口与后台证据来自同一个 CodeArts Session、Task、Run 和 Viewer 连接。
5. 在用户实时观看的同时，继续保存终端输入输出、屏幕帧、截图、视频、浏览器诊断、MCP Audit 和 RunEvent。

## 运行模式

Patch 至少提供以下两种明确模式：

- `headed/watch`：可见无人值守模式。正式人工见证验收默认使用此模式。
- `headless`：适用于 CI 或纯后台回归，行为保持无人值守，但不声称用户可实时观看。

模式必须由清晰的命令行参数或环境变量选择，并记录到会话 metadata 和 browser report 中。不得通过检测桌面环境后静默改变模式。

## 可见窗口要求

- 浏览器必须以 headed 模式启动，不能设置 `headless: true`。
- OpenChamber 浏览器必须导航到本次验收指定的原版页面，不得加载仓库自建的替代 GUI。
- CodeArts TUI 可见面固定为独立 xterm 窗口，必须订阅控制器正在操作的同一 ConPTY/PTY 会话与 output sequence；不得另外启动无关演示终端或第二个 CodeArts 会话。
- 两个可见窗口均应具有稳定、可区分的标题，并在测试报告中关联同一 sessionId。
- 默认窗口尺寸应保证 TUI 与 OpenChamber GUI 均可辨认；不得依赖用户手动缩放。
- Relay 或其他辅助进程可以隐藏控制台窗口，但不得隐藏两个正式被测窗口。
- 自动化结束后应保留最终状态至少一个可配置的观察窗口；默认不少于 10 秒，再由控制器自动关闭。失败时也必须展示失败状态和证据位置。

## 无人值守要求

- 授权完成后，测试全程不得要求用户点击页面、在 TUI 输入“继续”或处理普通工具许可。
- CodeArts 提示提交、阶段等待、固定 Bug 注入、技能需求提交和最终完成均由验收控制器自动驱动。
- 控制器只能依据权威 Task/Run/RunEvent、MCP 返回和浏览器验证结果推进阶段，不能依据模型自然语言声明提前通过。
- 长时间运行必须区分“慢”与“卡死”。总超时可以配置到 1 小时；卡死判定应综合最后 TUI 输出、工具调用、受管项目变更和 RunEvent 活动时间，并把判定依据写入报告。
- 不得通过自动发送无语义的“继续”来掩盖停顿或改变实验结果。

## 证据一致性要求

每次 `headed/watch` 验收必须保存并关联：

- CodeArts 版本、主模型、sessionId、Task ID、Run ID 和 projectId；
- TUI 输入、原始 VT 输出、受限屏幕帧和最终屏幕；
- 可见浏览器的视频、阶段截图及 viewport/window 信息；
- 浏览器 console、page error 和 failed request 诊断；
- MCP Audit、RunEvent 快照和最终状态；
- `headed`/`headless` 模式、窗口打开时间、关闭时间和观察保留时长。

屏幕帧和日志仍须有明确的数量或字节上限。达到上限时记录截断事件，但最终屏幕、生命周期、RunEvent 和浏览器报告仍必须落盘。

## 安全边界

- 可见模式不扩大 CodeArts、MCP 或浏览器的权限范围。
- 只允许访问 loopback Workbench、Relay、Viewer 和受管游戏预览地址。
- 不得部署、远程发布或执行抖音小游戏 preview、上传、提审、发布。
- 不得调用未授权的外部素材或模型 Provider。
- Viewer token 不得出现在页面正文、截图文件名、普通日志或最终报告中。

## 可执行验收条件

Patch 只有同时满足以下条件才可记录为完成：

1. 运行 `headed/watch` 验收命令后，系统自动出现一个真实可见的浏览器窗口。
2. 独立 TUI 窗口内可实时看到同一 sessionId 对应的 CodeArts 输出增长，OpenChamber GUI 保持原版页面。
3. 测试无需任何人工输入即可完成一次只读 smoke，且 browser report 为 `ok: true`、三类浏览器诊断均为零。
4. 完成一次真实主链验收时，两个独立被测窗口连续覆盖基线、固定 Bug 修复、技能追加和终态；Task/Run 证据连续且唯一。
5. headed 模式生成的视频、截图、终端证据和 RunEvent 均指向同一会话，时间范围相互重叠。
6. 自动化结束前两个被测窗口至少保留默认观察时长；最终报告记录通过或失败状态及证据目录，不要求修改 OpenChamber 页面显示测试状态。
7. 单元测试覆盖模式解析、headed 启动参数、观察保留时间和报告字段；可见 smoke 分别覆盖 TUI 实时更新与 OpenChamber 原版 GUI 操作。
8. `headless` 回归仍可运行，且报告不得把它标记为“用户实时可见”。

## 明确不接受的替代方案

- 只生成截图或视频，但运行时没有可见窗口。
- 只弹出一个静态 GUI 页面，实际 CodeArts 会话仍不可见。
- 把 CodeArts TUI、测试状态或证据面板嵌入 OpenChamber 产品页面。
- 要求用户手动打开 URL、刷新页面、输入提示或点击阶段按钮后才继续。
- 浏览器窗口可见，但自动化操作的是另一个 headless 浏览器上下文。
- 仅凭 TUI 文本中的“完成”判断验收通过。

## 交付报告要求

完成 Patch 后应汇报：修改文件、headed/watch 启动命令、headless 回归命令、实际执行结果、可见窗口证据、会话证据目录和剩余风险。未实际运行可见窗口验收时，不得声称本要求已经完成。
